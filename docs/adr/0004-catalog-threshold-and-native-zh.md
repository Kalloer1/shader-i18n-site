# 全量目录与 native-zh 标记

站点列表从"人工精选的 7 个光影"改为**自动同步的全量目录**：拉取 Modrinth 上全部 `project_type:shader` 的已审核项目，不做下载量门槛筛选——收录全部 870+ 个光影。每个光影均由翻译流水线生成 AI 初翻汉化文件；自带中文的光影（如 Complementary 系、Bliss）在目录数据中标记 `hasNativeZhCN: true`，在站点 UI 中显示"自带中文"标签，跳过翻译流程但仍保留在列表中供用户浏览。自动生成物（`modrinth-catalog.json`，轻量字段）与人工维护物（`shaders.json` 中的汉化版本映射）严格分离，按 Modrinth projectId 关联。站点保持静态（ADR-0002）：目录 JSON 由客户端按需 fetch + 分页渲染，不需要动态后端。

全量展示的好处：用户可以在一个站点浏览 Modrinth 上所有光影包的元数据、截图和介绍，无需逐个跳转 Modrinth 查看；自带中文的光影虽然不需要汉化文件，但展示其信息仍然有价值（方便用户发现和对比）。CurseForge 搜索全量翻页经实测不可用（分类过滤返回空、分类端点 404），故列表以 Modrinth 为唯一来源；CurseForge key 仅保留用于将来按 slug 精确补充元数据。

## Considered Options

- **全量收录 + 全量翻译 + native-zh 标记**（已采纳）：所有光影收录进列表，全部走 AI 翻译流水线，自带中文的标记跳过翻译但仍展示。站点内容最完整，用户体验最一致。
- 全量收录但不翻译自带中文的光影：与当前方案实际行为一致，但缺少明确的标记策略。被当前方案取代。
- 仅阈值过滤（≥1000 下载）+ 排除自带中文：早期方案，大幅缩减列表范围，用户发现光影的路径变窄。已被全量方案取代。
- Modrinth + CurseForge 双源全量再去重：CF 搜索全量不可用且两源高度重合，维护成本不值，被否决。
- 为承载全量列表升级动态网站：静态 JSON 按需加载 + 客户端分页完全够用，被否决。

## Consequences

- **正面**：站点覆盖 Modrinth 全部光影，成为最完整的 Minecraft 光影中文资源入口；用户无需离开站点即可浏览和对比任意光影。
- **正面**：`hasNativeZhCN` 标记清晰区分了"需要汉化"和"自带中文"两类光影，UI 展示和翻译流水线均可据此分流。
- **正面**：全量收录消除了"为什么这个光影不在列表里"的用户疑问。
- **负面**：目录 JSON 包含 870+ 条记录，客户端加载和渲染需要分页/懒加载优化。
- **负面**：翻译流水线需要为所有光影（含自带中文的）运行一遍检测流程，增加了构建时间，但实际翻译步骤会跳过已标记项。
