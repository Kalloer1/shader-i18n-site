# 用户问题记录

> **这是什么**：用户提出的每一个问题 / 现象的中文台账。不写空话，只记「用户看到了什么、为什么、怎么修的、证据在哪、现在什么状态」。
>
> **怎么用**：每条一行，按「现象 → 根因 → 处置 → 证据 → 状态」可追溯。查问题时先看现象定位到行，再顺着 sha / 文件:行号去复现。
>
> **日期分节**：一节一天。今天的问题写在 `## 2026-10-15` 一节里；以后新问题往后面**追加新的一节**，旧节不动。

> **证据规则**：每条都必须有能复现的证据（提交 sha（7 位）或 `文件:行号`）。**查不到就写「未找到」，绝不猜**。sha 的完整说明可用 `git log -1 --format="%h %s" <sha>` 复核。
>
> **状态图例**：`已修复` = 代码/数据已合并且验证通过；`已修复（仓库外）` = 修复不在本仓库，仓库里无法用 sha 复现。

### ⚠️ 别踩这个坑：「夸克」有两种意思

`site/data/glossary.json` 与 lang 文件里的「夸克」是 **Quark 模组的译名**，不是夸克网盘。
例如 `site/data/glossary.json:18723`：`"enables ropes from quark / ...": "使夸克/补充/农夫乐事模组中的绳索..."`。

**改「夸克网盘 → 国内镜像」时只能改网盘文案，绝不能全局替换「夸克」** —— 今天已经因为这事踩过一次。批量替换前先确认命中的是不是网盘语境。

## 今天攒下的工程教训

| 教训 | 说明 | 防它的具体机制 |
|---|---|---|
| `id` 是跨三处共用的键 | 同一个 `id` 同时出现在 `site/data/shaders.json`、磁盘路径（`site/public/lang/<id>/...`）、`data/lang-sources.json.gz` 三处 | 改一处必须同时想另两处；`npm run pack:lang` 是**合并式**重打包，别用覆盖式打包抹掉历史条目 |
| 本地绿 ≠ CI 绿 | 本地有 `sources/` 目录兜底（gitignored，16 MB），会掩盖 CI 里「找不到英文源」的失败 | 验证必须做 **CI 对等复跑**：临时 `Rename-Item sources sources.__hidden`，确认没有 `sources/` 也能过 |
| 两端各自实现同一筛选条件，必然漂移 | 列表页和详情页各写一套筛选/展示逻辑，改一边忘另一边 | 展示侧统一判据，生成器里已有注释强制这一点（见 `scripts/gen-shader-pages.mjs`、`site/.vitepress/theme/data.js`） |
| 「产物算出来 ≠ 产物入库」 | 两个 workflow 同时推 main 会互相挤掉，一整轮产物可能整批丢 | 推送必须 `pull --rebase` + 重试；**只有真推送成功才置 `pushed=true`**，别把「想推」当成「已推」 |
| 静默失败最贵 | Brevo 401、8 小时挂死、repack 误判失败、默认模型清单失效、镜像 CLI 缺失 —— 全都是「看起来正常其实没干成」 | 判失败要**独立于「发出去」**：先发布再变红（`continue-on-error` + 事后判红），失败必须留痕 |
| 诊断要能无副作用复现 | 在生产路径上做实验会污染真实数据 | 诊断脚本走只读/临时路径，探针与主流程分离 |
| 改完代码 ≠ 数据变了 | 代码改的是**行为**，标记/产物要等**下一次真实运行**才写进去 | 改完必须跑一次真实同步/翻译，再核对线上数据（今天 #17 就是例子；**#20 是第二个例子**——字段映射改完，还得等下一次目录同步才灌进数据） |
| 网关有账号级并发上限 | 翻译流水线 `LLM_CONCURRENCY=10`，一次跑 10 个并发请求，容易撞上限导致「跑一半大面积失败」 | 并发别拉满，撞限流时调低 `LLM_CONCURRENCY`，让单条失败不影响其余条目 |
| 接口返回 200 ≠ 页面能用 | 实测 `POST /verify-passphrase` 返回 **200** 就以为「口令能开」，结果前端按钮**根本没接线** | 新加的按钮/表单，验收清单必须有一条「在真浏览器里点一次」（这次靠真浏览器 CDP 点击才抓到） |
| 实测优先于假设 | 「forgecdn 支持按需缩放」是**假设**，实测 20+ 种尺寸**全 404** 才推翻 | 任何基于「服务端应该会…」的 URL 改写，先逐条实测 200 再写进代码 |
| 链接检查不能只查正文 | 检查器只查正文链接，漏掉导航里的死链（`/request.html` 404） | 检查器要覆盖导航/侧边栏/页脚等所有 `href` |
| 绝不要手打 secret / 口令 | 主管把 22 位口令的**第 2 位 `M` 打成了 `N`**，用户照抄必然失败；**更阴的是自测永远发现不了**——自测从**文件**读真值，所以一路 200 | 口令类值**一律程序化给出**（复制到剪贴板 / 指向文件），报告里**只写长度 / 哈希前缀** |
| 推理模型不能当翻译模型 | `content` 恒为空、内容在 `reasoning_content`；**不许**把 `reasoning_content` 当译文用（那是思考过程） | 首块 100% 回退就**立刻拉黑该模型**，并在队列 `error` 里给出人能看懂的原因 |
| 归一化只能吃掉「语义无关」的东西 | 大小写、连续空格、格式码可以归一；**单词一个字母都不能吃**（`OFF` ≠ `OFFS`、`Stars` ≠ `Stars Red`） | 改归一化规则必须跑**撞车检查**（同一骨架对应多个不同译文的骨架数必须为 0） |
| 「回退值」绝不能被缓存 | 否则英文原文会永久污染翻译记忆（本次 1,317 条） | 写入端与读取端**各加一道「值 ≠ 原文」守卫** |
| 给子代理的任务要能在 30 分钟内交报告 | 今天 **5 条 lane** 因「验证铺太开」而 30 分钟超时（其中 2 条**活干完了但没来得及汇报**，产物靠主管从磁盘上抢救） | 一个 lane 只干一件事；明确写「**拿不到证据就如实说拿不到**，不要反复试」；**限制能触发的 CI run 数** |
| 别只看「空字段」就下结论 | 队列里 `quark` 为空被当成「漏了镜像」，实际是**去重跳过的条目本就没有产物** | 判「缺」之前先做**不变量检查**（本次：`langVersions` 601 条中 quark 空 = 0、磁盘 601 目录 ↔ 登记 601 版本 1:1） |
| 验证要用远端数据，别用落后于远端的工作区 | 主管用工作区 `shaders.json` 扫出「0 条缺镜像」差点误导排查方向（工作区落后于 `origin/main`） | 核对数据一律 `git show origin/main:<path>` 或先 `git pull` |

## 新增一条的写法

1. 在**最新**的日期节下追加一行，编号接着排。
2. 五列都要有：现象（用户视角）→ 根因（代码/配置视角）→ 处置（sha）→ 证据（sha 或 `文件:行号`）→ 状态。
3. 证据查不到就写「未找到」，**不要猜、不要编 sha**。
4. 如果修的是同类问题的第 N 次，顺手在「工程教训」里补一条防它的机制。
