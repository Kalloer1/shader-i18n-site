# 项目结构

> 目的：让下一个人（或下一个 agent）一眼分清**哪些是人写的源、哪些是生成的产物、哪些是必须保留的数据**。
> 本文件只描述**目录职责**，不逐个文件罗列——逐个罗列必然过期。要查具体文件请直接看目录。

## 顶层结构

| 路径 | 是什么 | 是否入库 | 类型 | 备注 |
|---|---|---|---|---|
| `.github/` | 7 个 GitHub Actions workflow（`deploy` / `sync` / `translate` / `sync-worker-secrets` / 3 个探测） | 入库 | 人写的源 | `deploy.yml` 是唯一部署入口：测试 → lang 校验 → build → 部署 Worker → 部署 Pages |
| `scripts/` | 26 个 Node 脚本：抓目录、生成详情页、跑翻译流水线、校验/打包 lang、发布、镜像 | 入库 | 人写的源 | 用 `node scripts/<x>.mjs` 直接跑；UNC 路径下 `npm` 会静默跑 0 个测试，别用 npm 跑测试 |
| `scripts/lib/` | 8 个被 `scripts/` 复用的纯逻辑模块（`pipeline` 的池/交叉平台/术语表/CF API/lang-source 等） | 入库 | 人写的源 | 对应 `tests/` 里的单测 |
| `shared/` | 3 个跨 runtime 共享模块（`submit-limit` / `tencent-docs` / `zip-range`） | 入库 | 人写的源 | 同时被 `worker/` 和 `scripts/` 引用，改一处影响两端 |
| `worker/` | Cloudflare Worker：`/request` 表单、限流、内部状态回写 | 入库 | 人写的源 | 由 `deploy.yml` 部署，不是 Pages |
| `site/` | VitePress 站点根目录 | 入库（生成物除外） | 人写的源 + 生成的产物 | 见下 |
| `site/.vitepress/` | VitePress 配置与主题 | 部分入库 | 人写的源 + 生成的产物 | `config.mts`、`theme/` 入库；`cache/`、`dist/` 不入库 |
| `site/data/` | 站点运行时读取的 JSON（目录快照、`shaders.json`、`glossary.json`、版本缓存） | 入库 | 必须保留的数据 | `shaders.json` 是人工维护的版本映射，`modrinth/curseforge-catalog.json` 由脚本同步覆盖 |
| `site/public/lang/` | 542 个已发布汉化目录树（`<id>/<版本>/zh_CN.lang`） | 入库 | 必须保留的数据 | 站点产物本体；`.gitignore` 专门为它放行 `.zip` 结尾的版本目录 |
| `site/shaders/` | 每个光影一个详情页 `md`（构建期生成） | 不入库 | 生成的产物 | 由 `scripts/gen-shader-pages.mjs`（`npm run prebuild`）清空重建 |
| `site/.vitepress/dist/` | 构建出的静态站 | 不入库 | 生成的产物 | `deploy.yml` 部署的就是它 |
| `tests/` | 12 个 `node:test` 用例，覆盖 `scripts/lib/` 与 `shared/` | 入库 | 人写的源 | `node --test tests/*.mjs` |
| `docs/` | 流程/计划/问题记录/agent briefs | 入库 | 人写的源 | 本文件也在这里 |
| `data/` | `lang-sources.json.gz`：上游英文源打包（3 MB） | 入库 | 必须保留的数据 | CI 没有 `sources/`，lang 校验全靠它 |
| `sources/` | 上游英文源解包目录（约 564 个光影目录） | 不入库 | 生成的产物（可重建缓存） | 本地验证用；CI 不依赖它，删了要用 `scripts/fetch-lang-sources.mjs` 重新拉 |
| `node_modules/` | npm 依赖 | 不入库 | 外部依赖 | `vitepress` / `vue` / `wrangler` / `medium-zoom` |
| `.venv/` | 遗留的 Python 虚拟环境（uv，无任何脚本引用） | 不入库 | 外部依赖（疑似残留） | 仓库里没有 Python 代码，可直接删 |
| `.wrangler/` | `wrangler` 本地 miniflare 状态（KV/cache sqlite） | 不入库 | 生成的产物 | 本地 dev 缓存，可删 |
| `artifacts/` | 历史首页截图与翻译/镜像运行日志 | 入库 | 生成的产物 | 已入库的历史留档，不是源 |
| `prototypes/` | 三版首页原型 HTML（direction-a/b/c） | 入库 | 人写的源（历史原型） | 只作参考，不参与构建 |
| `package.json` / `package-lock.json` | 依赖与脚本入口 | 入库 | 人写的源 | `npm run build` 会自动先跑 `prebuild` |
| `wrangler.toml` | Worker 配置（入口、KV 绑定、路由） | 入库 | 人写的源 | 与 `worker/index.js` 成对 |
| `FLOW.md` | 全流程 Mermaid 图（采集 → 翻译 → 发布） | 入库 | 人写的源 | 看图找链路 |
| `README.md` | 项目架构、状态、决策、待办的唯一来源 | 入库 | 人写的源 | 项目状态以它为准 |
| `AGENTS.md` | 本地 Agent/MCP 环境清单 | 入库 | 人写的源 | 不是产品文档 |
| `.gitignore` | 忽略规则 | 入库 | 人写的源 | 生成物、密钥、`sources/` 都靠它挡 |
| `start-translation.ps1` / `.cmd` | 本地跑翻译流水线的入口（注入 `LLM_MODELS` 等环境变量） | 入库 | 人写的源 | 会提示输入 API Key，不落盘 |

## 生成物 / 可安全删除

删掉后都能重建，删了不影响 CI（CI 从零构建）：

- `site/shaders/` — `npm run prebuild` 重建
- `site/.vitepress/dist/`、`site/.vitepress/cache/` — 下次构建重建
- `.wrangler/` — 下次 `wrangler dev` 重建
- `sources/` — `scripts/fetch-lang-sources.mjs` 重新拉（本地验证要用，别随手删）
- `.venv/` — 无引用残留
- 仓库根出现过的 `.vitepress/`（`site/.vitepress/` 才是真配置目录，根上那个只会是 Vite 临时缓存）

## 绝对不要动

- `site/public/lang/**` — 已发布的汉化文件本体，站点交付物
- `site/data/shaders.json`、`site/data/glossary.json` — 人工维护的版本映射与术语表，覆盖即丢数据
- `data/lang-sources.json.gz` — CI 校验 lang 的唯一英文源
- `sources/` — 本地验证的英文源，CI 对等复跑时会临时改名成 `sources.__hidden`，**验完必须改回来**（`sources` 不存在而 `sources.__hidden` 存在 = 事故）
- `.github/`、`worker/`、`scripts/` 的已跟踪文件 — 改它们属于功能变更，不是清理
- `docs/用户问题记录.md` — 踩坑历史，只追加不删
